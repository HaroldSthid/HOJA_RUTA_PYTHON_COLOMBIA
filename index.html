Principios de la Ruta

Aprender haciendo

Proyectos desde el primer dia. La teoria nunca se dicta en bloques mayores a 25 minutos sin codigo de por medio.

print("Hola")
ejecutar()

Intuicion primero

Priorizar la intuicion antes que la teoria. Los conceptos se anclan en ejemplos visuales y cotidianos antes de formalizarse.

ver = lambda x: print(x)

Sin sobre-ingenieria

Evitar inicialmente bases de datos, desarrollo web, frameworks y arquitectura de software. Primero productividad real.

import this

Para cualquier profesion

Enfoque practico que permite a cualquier persona descubrir como Python puede aumentar su productividad, independientemente de su area.

python archivo.py

Ejemplos visuales

Explicar conceptos con representaciones graficas y casos cotidianos. El error se ve, no solo se lee en una terminal.

rect(10, 10, 80, 80)
Resultado esperado: Al finalizar la ruta, el estudiante comprendera los fundamentos del pensamiento computacional, sera capaz de escribir programas sencillos en Python y tendra una base solida para continuar hacia areas como automatizacion, analisis de datos, inteligencia artificial o desarrollo de aplicaciones.

Temas y subtemas

Tema 0Preparacion del entorno2 h

Instalacion y validacion del espacio de trabajo. Una configuracion erronea impide el progreso, por lo que se aborda como unidad critica con sus propios hitos de finalizacion.

  • Instalacion de Processing y habilitacion del Python Mode.
  • Componentes del editor: lienzo de codigo, funcion Run, consola y ventana de visualizacion.
  • Gestion de sketches: organizacion de ficheros, guardado y nomenclatura.
  • Interpretacion de fallos: sintaxis, sangria y referencias no definidas.

Referencia: Cap. 1 — Processing Installation and Python Mode Setup.

Tema 1Coordenadas y graficos8 h · 3T / 5P

El lienzo como sistema cartesiano. El origen esta en la esquina superior izquierda; el eje Y crece hacia abajo.

  • Sistema de coordenadas: size(), width, height.
  • Primitivas 2D: point(), line(), rect(), ellipse().
  • Color y estilo: RGB, HSB, hexadecimal; fill(), stroke(), background().
  • Formas complejas: curve(), bezier(), beginShape(), vertex().
  • Variables al servicio del dibujo: disenos parametrizables con operador %.
  • Texto como elemento grafico: text(), alineacion y tamano.

Referencias: Capitulos 1, 2 y 3.

Tema 2Condicionales if6 h · 2T / 4P

La evaluacion booleana se materializa en cambios visuales en el lienzo.

  • Tipos logicos True / False; valores falsy.
  • Operadores: ==, !=, >, <, >=, <=.
  • Arquitectura if, elif, else: sintaxis e indentacion.
  • Operadores logicos: and, or, not.
  • Mapeo de cuadrantes; alteracion de propiedades visuales segun estado.

Referencia: Capitulo 4.

Tema 3Bucles for y while9 h · 3T / 6P

La iteracion como motor de complejidad: desde mallas geometricas hasta mosaicos generativos.

  • Bucle while: condicion de permanencia, prevencion de bucles infinitos.
  • Bucle for y range(): inicio, fin, salto.
  • Control: break y continue.
  • Estructuras anidadas: rejillas 2D (filas x columnas).
  • Aleatoriedad: random(), randomSeed(), nociones de noise().
  • Arte generativo: teselas de Truchet, simetria y repeticion visual.

Referencia: Capitulo 5.

Tema 4Funciones y reutilizacion8 h · 3T / 5P

El principio DRY aplicado al diseno visual. Transicion entre escribir lineas y disenar estructuras de software.

  • Declaracion def, parametros posicionales, keyword arguments, valores predeterminados.
  • Sentencia return: subrutinas que dibujan vs. subrutinas que devuelven datos.
  • Scope: jerarquia local/global; uso responsable de global.
  • Calculo para animacion: sin(), cos(), radians(), map(), lerp(), dist().

Referencia: Capitulo 9 + complementos del Capitulo 1.

Tema 5Proyectos visuales interactivos7 h · 2T / 5P

La variable del tiempo entra al lienzo: animaciones y mecanismos de interaccion.

  • Ciclo de animacion: setup() y draw(); frameRate, frameCount.
  • Transformaciones: translate(), rotate(), scale(); pushMatrix() / popMatrix().
  • Deteccion de colisiones: rebotes con dist().
  • Interactividad: mouseX, mouseY, mousePressed(), keyPressed().
  • Listas para gestion de multiples entidades graficas.
  • Exportacion: saveFrame().

Referencias: Capitulos 6, 7 y 11.

Temas y subtemas

Tema 0Del sketch al script: entorno real4 h · 1.5T / 2.5P

El salto mas significativo de la ruta: de la interfaz grafica de Processing a ficheros .py ejecutados desde la terminal.

  • Instalacion Python 3.12+ y python --version.
  • VS Code: extensiones, jerarquia de carpetas, panel de comandos.
  • Modalidades: REPL, scripts .py y celdas de notebook. Criterios de seleccion.
  • Terminal: python archivo.py, navegacion por rutas.
  • Jupyter: Shift+Enter, persistencia de variables, gestion del kernel.
  • PSL vs. PyPI; introspeccion con type(), len(), dir(), help().
  • Lectura inversa de tracebacks para localizar el fallo.
  • Comentarios # y docstrings (PEP 257).
Advertencia: el obstaculo mas recurrente es la discrepancia entre la ubicacion del script y el directorio de trabajo actual. Dedicar tiempo a esto.
Tema 1Listas y diccionarios — Big 414 h · 4.5T / 9.5P

De variables aisladas a colecciones organizadas. Criterio tecnico para seleccionar la arquitectura optima segun la naturaleza del problema.

  • 1.1 Cadenas: .split(), .strip(), .replace(), .lower(), .upper(); indexacion y slicing.
  • 1.2 Listas: .append(), .insert(), .remove(), .pop(), .sort(); enumerate(); estructuras anidadas.
  • 1.3 Tuplas: inmutabilidad; desempaquetado; funciones con retornos multiples.
  • 1.4 Conjuntos: set() para deduplicacion; intersecciones y diferencias.
  • 1.5 Diccionarios: .keys(), .values(), .items(); acceso defensivo con .get().
  • 1.6 Arquitecturas compuestas: diccionarios anidados; inspeccion con pprint.
  • 1.7 Criterios de seleccion: orden, mutabilidad, metodos de busqueda y duplicidad.

Head First Python, caps. 1, 2 y 5.

Tema 2Lectura y escritura de archivos10 h · 3T / 7P

Transicion a la persistencia de datos. Consumir flujos externos y generar archivos interoperables.

  • 2.1 Lectura: open(), modos 'r' 'w' 'a'; gestor with open(...) as f:.
  • 2.2 Rutas: encoding='utf-8'; os.path.join(); rutas relativas vs. absolutas.
  • 2.3 Salida: .write(); reportes desde estructuras en memoria.
  • 2.4 F-strings: {:.2f}, {:>10}, {:,}.
  • 2.5 CSV/JSON: csv.DictReader; json.load() y json.dump().
  • 2.6 HTML/SVG: generacion por codigo; webbrowser.
  • 2.7 Datos sucios: deteccion de inconsistencias; descarte selectivo con log.

Head First Python, caps. 2 y 4.

Tema 3Automatizacion de tareas simples10 h · 3T / 7P

"Como aplico esto en mi entorno laboral?" Automatizacion de flujos repetitivos sobre sistemas de archivos.

  • 3.1 Modulo os: os.listdir(), os.path.exists(), os.makedirs(); pathlib.Path.
  • 3.2 Ciclo: indexacion → filtrado → recorrido → ejecucion → acumulacion → reporte.
  • 3.3 Seguridad: shutil.copy2(), shutil.move(); protocolo de simulacion obligatorio.
  • 3.4 Cronologia: datetime.now() y .strftime() para marcas temporales.
  • 3.5 Registro: registro.txt acumulativo con fecha, aciertos y omisiones.
  • 3.6 PSL: glob, random, time.sleep(), webbrowser.
  • 3.7 Etica: priorizar duplicados; proteccion de datos sensibles.

Head First Python, cap. 3 + modulos de la PSL.

Tema 4Organizacion del codigo8 h · 2.5T / 5.5P

De script funcional a arquitectura de proyecto profesional que cualquier colaborador puede interpretar y mantener.

  • 4.1 Modularizacion: principio DRY; def, responsabilidad unica.
  • 4.2 Modulos externos: import; nombres cualificados; alias; __pycache__.
  • 4.3 Arquitectura: carpetas src/, datos/, salida/; if __name__ == "__main__":.
  • 4.4 PEP 8: 4 espacios, snake_case, docstrings (PEP 257).
  • 4.5 README: requisitos, ejecucion y resultados esperados.
  • 4.6 Git: flujo basico, .gitignore, publicacion como bonificacion.

Head First Python, cap. 3.

Proyecto integrador: "Cuentas Claras"

Mini sistema de reporte de gastos personales. Una persona exporta sus movimientos en CSV por mes. Al final del trimestre quiere: informe legible, grafico de barras por categoria, archivo reutilizable. Solo Python + Biblioteca Estandar.

Datos: carpeta datos/ con gastos_2026-01.csv, gastos_2026-02.csv, gastos_2026-03.csv; columnas fecha, categoria, descripcion, monto.

Duracion: 6 h de taller final + trabajo incremental durante el modulo.

Prueba de fuego: el dia de cierre cada participante recibe datos desconocidos — mes adicional, categoria nueva, 3 defectos nuevos — y tiene 10 minutos para procesarlos. Un proyecto que solo funciona con sus propios datos no esta terminado.
